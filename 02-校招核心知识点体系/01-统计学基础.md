# 校招统计学基础全解

> 统计学是数据分析的"内功"。校招面试中，统计学不单独成卷，而是**渗透在每一道业务题里**：算平均客单价时考你中位数 vs 均值的选型，做AB实验时考你假设检验与样本量，看渠道数据时考你辛普森悖论。本篇按校招真实考察密度组织为六大模块：**描述统计 → 概率分布 → 假设检验 → AB测试 → 抽样方法 → 统计悖论**，每个知识点均包含：定义、公式、业务场景、常见误区、面试问答、计算案例六要素。
>
> **学习路线建议**：校招备考不必啃数理统计教材，按"描述统计（1天）→ 假设检验（2天）→ AB测试（3天）→ 悖论（1天）"的优先级即可，概率分布与抽样作为支撑模块穿插学习。本篇所有计算案例均可手算复现。

## 第一节 描述统计：用少数数字概括一批数据

描述统计回答一个问题：**手里有一堆数，怎么用几个数字把它的"长相"讲清楚？** 一切从三个维度展开：数据集中在哪里（集中趋势）、散得开不开（离散程度）、往哪边歪（分布形态）。

### 1.1 集中趋势：均值、中位数、众数

#### 定义与公式

| 指标 | 定义 | 公式 | 适用数据 |
|---|---|---|---|
| 算术均值 | 所有值加总除以个数 | $\bar{x} = \frac{1}{n}\sum_{i=1}^{n} x_i$ | 数值型，分布近似对称 |
| 加权均值 | 各值乘权重后平均 | $\bar{x}_w = \frac{\sum w_i x_i}{\sum w_i}$ | 分组数据、有天然权重 |
| 中位数 | 排序后位于正中间的值（n为偶数取中间两数均值） | 位置 = $\frac{n+1}{2}$ | 数值型/有序，任意分布 |
| 众数 | 出现次数最多的值 | —— | 类别型、数值型均可 |

#### 业务场景：为什么"平均"经常骗人

- **配送时长/响应时长**：美团外卖配送时长、客服响应时长这类数据是**右偏分布**（大多数人10-30分钟，少数异常单2小时）。用均值会被极端值拉高，行业惯例是看 **P50（中位数）与P90**。
- **薪酬/房价**：右偏严重的经典场景。"平均年薪"被高管拉高，中位数才代表普通人——这也是为什么国家统计局同时公布两个数。
- **付费金额**：游戏/电商的付费金额极度右偏（大R一笔顶一万笔），看ARPU时会同时看ARPPU与付费金额中位数。
- **品类SKU定价**：服装尺码、鞋码用众数（哪码卖得多补哪码），均值0.5码没有意义。

#### 常见误区

1. **【避坑指南】右偏分布只报均值。** 面试官问"某业务平均响应时长上升但用户投诉没变多，为什么？"标准答案链：均值被极端值拉高 → 看中位数/P90分布 → 可能只是长尾恶化而主流体验没变。这一问在本库《面试真题全解》里还会以完整形式出现。
2. **均值对异常值敏感，中位数不敏感**：数据里混入一笔异常大额订单，均值立刻失真，中位数几乎不动。清洗前先用中位数感知"真实水平"。
3. **众数不唯一**（可能有两个众数）且连续数据几乎每个值只出现一次，此时众数无意义，需先分箱。

#### 计算案例

某店铺一周日销售额（万元）：`3, 4, 4, 5, 6, 7, 40`（最后一天有大促）。
- 均值 = (3+4+4+5+6+7+40)/7 = 69/7 ≈ **9.86**
- 中位数 = 排序后第4个 = **5**
- 众数 = **4**

业务解读：均值9.86比中位数5高出近一倍，说明销售额被大促日（40）严重拉高；评估"日常经营水平"应看中位数5，评估"含促销的综合产出"才用均值。**先问业务问题是什么，再选统计量**——这是描述统计的第一原则。

#### 面试问答

- **问：均值和中位数什么时候差异大？说明了什么？** 差异大⇒分布偏斜。均值>中位数⇒右偏（存在大极端值），均值<中位数⇒左偏。差异越大偏得越厉害，此时均值代表性下降。
- **问：GMV指标该看均值还是中位数？** 看目的：GMV总量本身是加总指标不存在此问题；客单价若用于"评估用户画像/体验"看中位数，用于"计算收入预测"必须用均值（收入=订单量×均值客单价，代数上只有均值成立）。

### 1.2 离散程度：极差、方差、标准差、变异系数

#### 定义与公式

| 指标 | 公式 | 说明 |
|---|---|---|
| 极差 | $R = x_{max} - x_{min}$ | 最粗糙，只看两端 |
| 方差 | $s^2 = \frac{1}{n-1}\sum (x_i - \bar{x})^2$ | 量纲是原单位的平方，不便解读 |
| 标准差 | $s = \sqrt{s^2}$ | 与原数据同量纲，最常用 |
| 变异系数 | $CV = s / \bar{x}$ | **无量纲**，用于比较不同量纲/不同水平的波动 |

为什么除以 n-1 而不是 n：样本方差用 n-1（贝塞尔校正）是为了无偏估计总体方差——样本均值本身就"吸收"了一部分离差，除以n会系统性低估。

#### 业务场景

- **AB测试前置检查**：比较两个渠道的转化率稳定性，均值都是3%，但A渠道日波动标准差0.2%、B渠道1.5%——B渠道均值不可靠，实验要更长周期。
- **库存管理**：两类商品日均销量都是100件，A标准差10件、B标准差60件，B需要更高安全库存。安全库存 ≈ 服务水平系数 × σ × √提前期。
- **跨指标比较必须用CV**：比较"销售额波动"和"订单量波动"不能直接比标准差（量纲不同：万元 vs 单），用CV（σ/均值）才公平。**【面试高频】**

#### 计算案例

两名客服近5日处理单量：甲 `90, 95, 100, 105, 110`，乙 `50, 80, 100, 120, 150`。两人均值都是100。
- 甲：离差均±10，s≈15.8，CV=15.8%
- 乙：s≈39.5，CV=39.5%

业务解读：乙产量"看起来"也有100，但稳定性差，排班与SLA承诺应基于甲；乙需要排查原因（技能不熟练？单量来源波动？）。

#### 面试问答

- **问：两组数据均值不同，怎么比较谁更分散？** 用变异系数CV，消除量纲与水平差异。补充：若问的是分布位置差异则看分位数。
- **问：方差的平方为什么要开方再用？** 保持与原数据同量纲，否则"元²""件²"无法业务解读。

### 1.3 分位数与箱线图：比均值更"诚实"的视角

#### 定义与公式

- **p分位数**：至少p%的数据 ≤ 它。常用P25/P50/P75、P90、P95、P99。
- **四分位距 IQR = P75 − P25**：中间50%数据的跨度，是稳健的"离散度量"（不受两端极端值影响）。
- **箱线图异常值判别**（Tukey法则）：低于 `P25 − 1.5×IQR` 或高于 `P75 + 1.5×IQR` 的点视为疑似异常值；3倍IQR之外为极端异常值。

#### 业务场景

- **SLA承诺**：物流承诺"次日达"不能按均值承诺，要看P90妥投时长——90%的用户能在该时间内收到，否则一半用户天天被"平均"。
- **风控阈值**：支付金额>P99作为大额监控线，而非均值+3σ（金额右偏、非正态时3σ法则失真）。
- **异常检测双引擎**：近似正态数据用3σ法则，偏态数据用IQR/分位数法。**【加分点】** 能主动区分这两种适用条件。

#### 计算案例

11个用户的会话时长（分钟）：`2, 3, 3, 4, 5, 5, 5, 6, 7, 8, 60`。
- P50 = 5；P25 ≈ 3，P75 ≈ 7（n=11时 P25取第3个数、P75取第9个数，不同软件插值法略有差异，面试说明即可）
- IQR = 4，上界 = 7 + 1.5×4 = 13 → **60 被判为异常值**，而均值+3σ法：均值≈9.8、s≈17，3σ上界≈61，恰好漏判。偏态数据IQR法更稳。

#### 面试问答

- **问：为什么SLA看P90不看均值？** SLA是"对每个用户的服务承诺"，均值会被少数超长单稀释；P90直接回答"90%的用户多久能被服务到"，与承诺语义一致。
- **问：P90上升但P50不变说明什么？** 主流用户体验没变，长尾（尾部10%的慢单）恶化——常指向个别环节：特定区域运力、特定支付通道超时、大批量订单等，是异动归因的第一层切法。

### 1.4 分布形态：偏度与峰度

#### 定义

- **偏度（Skewness）**：衡量分布不对称方向与程度。右偏（正偏）：长尾在右、均值>中位数，如收入、订单金额、响应时长；左偏（负偏）：长尾在左、均值<中位数，如easy考试分数。
- **峰度（Kurtosis）**：衡量尾部厚度/尖峰程度。正态分布峰度=3（超额峰度=0）；尖峰厚尾>0意味着极端值出现频率高于正态假设——金融风控特别在意这一点（"肥尾"意味着黑天鹅更常见）。

#### 业务场景与误区

- **付费金额右偏** → 做AB实验时该指标方差被大R主导，改用**对数变换**或改核心指标为"人均付费人数（付费率）"这种近似二元的指标。
- **【避坑指南】把正态检验当仪式。** 不是所有场景都要正态：转化率大样本下按中心极限定理近似正态即可；真正的错误是对右偏金额直接套"均值±3σ"。
- 偏度只是"症状"，业务上重要的是追问长尾来源：是正常业务形态（大R），还是数据问题（测试单、刷单）。

#### 面试问答

- **问：数据右偏，想让均值更有代表性，怎么办？** 三选一：报中位数/分位数；对数变换后再用均值（几何意义上）；截尾均值（去掉前后1%再算）。并说明业务含义差异。

### 1.5 描述统计综合案例：从一张订单明细到经营判断

场景：你是某电商的数据分析师，运营同学说"6月客单价下降了，是不是用户变穷了"。订单数据（简化）：5月与6月各10000单，字段含 `order_id, user_type(新/老), amount`。

分析四步：
1. **先确认口径**：6月是否新上了一个低客单品类（如9.9包邮）？是否把0元试用单算进来了？——口径问题占"数据异动"的三成。
2. **看分布不看均值**：5月客单价均值86元/中位数62元；6月均值79元/中位数64元。均值降了但中位数反升——典型右偏减弱，即**高客单大单变少了**，普通用户客单价没变。
3. **分层验证**：按新老客拆分，老客客单价持平，新客客单价从95元降到52元——新客占比从15%升到35%（大促拉新），结构变化拉低整体均值。
4. **结论**：不是"用户变穷"，而是**新客占比提升的结构效应 + 大单减少**。这个思路就是"异动归因"的雏形，在本库《业务分析方法论》模块会系统化展开。

**【面试高频】** "均值降中位数升"是校招面试的经典陷阱题，答案永远指向：分布形态变化或结构变化，而非整体水平变化。

### 1.6 本节面试问答速查

1. **给一列数据，你会先看什么？** 先看量级与单位（head/描述统计）→ 看缺失与重复 → 看分布（直方图/箱线图判断偏态与异常）→ 再选统计量。
2. **异常值怎么处理？** 先查因：录入错误→修正/剔除；真实极端值→保留但用稳健统计量（中位数/IQR），或分群单独分析；业务规则内的大额（大R用户）→绝不剔除，单独分层。
3. **均值、中位数、众数分别什么时候用？** 对称连续→均值；偏态连续/有序→中位数；类别→众数；报告里最好"均值+中位数"并列，差异本身就是信息。
4. **什么是辛普森悖论的预警信号？** 分组看结论与整体看结论相反——本章第六节详述。

## 第二节 概率分布与中心极限定理：数据"长什么样"决定你"用什么方法"

> 校招不考你推导分布密度函数，但要求你**听到业务指标能对上分布类型**：转化率→二项，单位时间进线量→泊松，金额→右偏/对数正态，抽样均值→正态（CLT）。对上分布，才知道检验方法、知道方差异动正不正常。

### 2.1 二项分布：一切"是/否"指标的总纲

#### 定义与公式

n 次独立重复试验中"成功"次数 X 的分布，单次成功概率为 p：

$$P(X=k) = C_n^k \, p^k (1-p)^{n-k}, \quad E(X)=np, \quad Var(X)=np(1-p)$$

#### 业务场景

- 用户看到广告后**是否点击**、加购后**是否支付**、试用后**是否付费**——转化率类指标天然是二项分布：n个用户、每人独立"成功/失败"。
- 衍生：**比例的标准误** $SE = \sqrt{p(1-p)/n}$——AB测试算转化率置信区间、算样本量的核心公式。

#### 近似正态的条件

n·p ≥ 5 且 n·(1−p) ≥ 5 时，二项可用正态近似。**【避坑指南】** 小流量实验（比如每组200人、转化率1%）不满足条件，正态近似失效，要用精确二项检验或贝叶斯方法——这是高级面试的追问点。

#### 计算案例

某落地页历史转化率 p=10%，今天来了 300 个访客。期望转化人数 = 300×0.1 = 30，标准差 = √(300×0.1×0.9) ≈ 5.2。今天实际转化 46 人，(46−30)/5.2 ≈ 3.1 个标准差——若页面没改版，这属于极小概率事件，提示"今天流量结构有问题"（比如被渠道刷量），而不是运气好。

### 2.2 泊松分布：单位时间内的"计数"指标

#### 定义与公式

单位时间/空间内随机事件发生次数 X，平均发生 λ 次：

$$P(X=k) = \frac{\lambda^k e^{-\lambda}}{k!}, \quad E(X)=Var(X)=\lambda$$

#### 业务场景

- 每分钟客服进线量、每分钟订单到达量、每天支付通道报错次数、每千次曝光的投诉数。
- 运力排班：若客服中心平均每小时进线 λ=60 通，按泊松可推算"进线超过80通"的概率，决定要不要安排机动坐席——这就是"泊松排班"的直觉来源。
- 泊松与二项的关系：n大、p小、np=λ 适中时，二项≈泊松（稀有事件近似）。

#### 误区

- 泊松假设事件**独立、速率恒定**。订单到达有明显早晚高峰（速率不恒定），严格说应分段建模或用非齐次泊松；面试时点出这个假设瑕疵是**【加分点】**。
- 计数数据高度右偏（λ小的时候），别用"均值±3σ"做异常监控。

### 2.3 正态分布：大部分统计方法的"默认世界观"

#### 定义与关键数字

概率密度关于均值对称的钟形曲线。记住三条：

$$P(\mu \pm 1\sigma) \approx 68.3\%, \quad P(\mu \pm 2\sigma) \approx 95.4\%, \quad P(\mu \pm 3\sigma) \approx 99.7\%$$

标准化：$z = \frac{x-\mu}{\sigma}$，任何正态变量标准化后都服从标准正态——这是查表/用z值沟通的桥梁。

#### 业务场景

- 质量监控：包装重量、零件尺寸天然近正态，控制图（±3σ限）就建在正态假设上。
- **相对值比较**：用户"消费金额在全体用户中的百分位"（如前5%），就是 z→百分位的映射，会员等级常用。

#### 误区

- **【避坑指南】看到连续数据就当正态。** 金额、时长类几乎必然右偏。判断方法：直方图/QQ图，或均值与中位数差距。偏态数据用分位数或先对数变换。
- "95.4%在±2σ内"是对**正态总体**说的，对任意分布不成立（切比雪夫不等式只保证 ≥75%）——曾有面试官专门用这一点筛人。

### 2.4 中心极限定理（CLT）：AB测试之所以成立的根

#### 定义

不管总体服从什么分布，只要独立同分布、方差有限，**样本均值的分布**在样本量足够大（经验法则 n≥30）时近似正态：

$$\bar{X} \approx N\left(\mu, \frac{\sigma^2}{n}\right)$$

样本均值的方差是总体方差的 1/n——**样本量越大，均值越稳**，这就是"为什么3000人的实验组均值可以当真"的数学根基。

#### 业务场景（必须能讲出来）

问：某平台人均客单价分布高度右偏（大部分人30元、少数人3000元），为什么AB实验还能用z/t检验比较"人均客单价"？

答：CLT保证的是**组均值**的抽样分布近似正态，而不是原始数据正态。每组样本量上万时，组均值的分布足够正态，均值的假设检验有效。补充严谨性：若样本量小且指标极端偏态（比如仅几十个付费用户比ARPPU），CLT近似差，应改比较"付费率"这类二元指标或用Bootstrap/置换检验。**【加分点】**

#### 大数定律一句话

样本量越大，样本均值越趋近总体期望——它说的是"均值收敛"，CLT说的是"均值怎么分布"，两者别混。面试能一句话区分即加分。

### 2.5 指数分布（了解即可）

事件间隔时间：两次进线之间隔多久、设备两次故障之间隔多久。与泊松是一对（泊松数"个数"、指数量"间隔"）。无记忆性是它的标志性质。校招只要能说出适用场景与"无记忆性"三个字即可。

### 2.6 本节面试问答速查

1. **转化率是什么分布？** 单个用户是伯努利（0-1），n个用户合计转化数是二项；p未知用样本比例估计；np、n(1-p)够大时近似正态。
2. **为什么样本均值能近似正态？** 中心极限定理；条件：独立同分布、方差有限、n≥30（经验值）；强调是"均值的分布"正态而非数据本身。
3. **泊松分布在业务里怎么用？** 单位时间计数指标建模与排班/异常监控；注意独立性假设在高峰期会破。
4. **两个渠道转化率3%和3.2%，能说B更好吗？** 不能直接说——差异是否显著取决于流量（标准误），这正是假设检验的问题，引出下一节。

## 第三节 假设检验：从"看起来更好"到"统计上更好"

> 业务里每天都有人喊"新版本转化率高了0.8%，快全量"。假设检验回答的唯一问题是：**这点差异，是真实提升，还是随机波动？** 校招技术面必考，且几乎一定让你解释p值。

### 3.1 假设检验的思想与五步流程

思想是**反证法**：先假设"没有效果"（原假设H₀），观察数据在这种假设下出现的稀有程度——太稀有了就推翻H₀。

五步流程（面试可以直接背这个框架）：

1. **设定假设**：H₀（无差异/无效果，默认保守立场）vs H₁（有差异）。"默认保守"的原因：把"有效"的举证责任交给数据，防止我们把随机波动当成成果。
2. **选检验统计量与显著性水平 α**：比例差异用z检验、均值差异用t检验、类别关联用卡方；α通常取0.05。
3. **计算统计量与p值**：在H₀成立的前提下，得到"当前样本或更极端结果"的概率。
4. **决策**：p < α ⇒ 拒绝H₀，称"统计显著"；p ≥ α ⇒ 不拒绝H₀（注意：不等于"H₀成立"）。
5. **业务结论**：统计显著 ≠ 业务显著，见3.7。

### 3.2 p值：被误读最多的统计学概念

**定义（背原话）**：在原假设成立的前提下，观察到当前样本结果或更极端结果的概率。

**四大常见误读（面试官最爱挖的坑）**：

| 误读说法 | 错在哪 |
|---|---|
| "p=0.03 表示H₀有3%的概率为真" | p值不建立在H₀为真的概率上；频率学派中H₀没有"概率为真"一说 |
| "p=0.05 表示结果有95%的概率可复现" | 可复现概率与p值无直接换算关系 |
| "p>0.05 说明两组无差异" | 只说明"证据不足以判定差异"，可能是样本量不够；**不显著 ≠ 无差异** |
| "p=0.001 比 p=0.04 效果大得多" | p值大小受效果量与样本量双重影响，不直接度量效果大小；比效果要 Report 效应量（提升幅度）与置信区间 |

**【面试高频】** "解释一下p值"几乎是统计环节必考第一题。高分解法：先背定义，再主动补充"p值小说明'纯随机波动解释当前差异'的概率低"，最后补一句"所以我还会看置信区间和业务提升幅度"。

### 3.3 两类错误与统计功效

| | 真实情况：无效果 | 真实情况：有效果 |
|---|---|---|
| **结论：有效果** | 第一类错误 α（假阳性，把波动当提升） | 正确（功效 1−β） |
| **结论：无效果** | 正确 | 第二类错误 β（假阴性，把提升漏掉了） |

- **α**：显著性水平，通常0.05——愿意承受5%的概率"冤枉"（上线了其实无效的改动）。
- **功效 Power = 1−β**：真实有效时能检验出来的概率，行业惯例≥80%。功效不足的实验"测不出"真实提升，结论形同虚设。
- **权衡**：样本量固定时α与β此消彼长；**唯一的双赢路径是加大样本量**（或提升效果本身的幅度）。面试被问"α能不能设成0.001"时，答：可以但功效骤降，需要数倍样本量，权衡业务试错成本。

**【加分点】** 主动说出"假阳性成本"的语境差异：医疗诊断宁可假阴性；互联网实验假阳性成本只是回滚一次，所以α=0.05够用——体现统计思维落在业务上。

### 3.4 常用检验方法选型表（背下来）

| 数据情况 | 方法 |
|---|---|
| 两组比例（转化率）比较，大样本 | 两比例z检验（或卡方检验，二者等价） |
| 两组均值（人均时长/客单价）比较 | 独立样本t检验（方差齐性用普通t，不齐用Welch t） |
| 同一批用户前后对比（改版前后同一用户） | 配对t检验 |
| 两组类别构成比较（渠道×是否流失） | 卡方检验（期望频数<5用Fisher精确检验） |
| 小样本/分布未知/偏态严重 | 秩和检验（Mann-Whitney U）或Bootstrap |
| 多组比较 | 方差分析ANOVA，事后配对比较需校正（Bonferroni） |

### 3.5 单侧 vs 双侧

- 双侧：H₁: μ_A ≠ μ_B，检测"任何方向的差异"，α平分到两侧，是AB测试默认。
- 单侧：H₁: μ_B > μ_A，只在有先验方向时用（比如只关心新版是否"更差"做风险监测）。**【避坑指南】** 先看数据再决定单双侧=偷看答案，会虚减p值；必须在实验设计阶段定好。

### 3.6 完整计算案例：按钮颜色实验（两比例z检验手算）

实验组（红色按钮）：n₁=5000，转化 x₁=260，p̂₁=0.052；对照组（蓝色）：n₂=5000，x₂=200，p̂₂=0.040。问：红色按钮转化率是否显著更高？

```
第1步 合并比例：p̂ = (260+200)/(5000+5000) = 0.046
第2步 标准误：SE = √( p̂(1-p̂)(1/n₁+1/n₂) )
             = √(0.046×0.954×(0.0002+0.0002)) = √(0.0000439×0.0004)... 
             精确计算：0.046×0.954=0.043884；×0.0004=0.00001755；开根 ≈ 0.00419
第3步 z统计量：z = (0.052−0.040)/0.00419 ≈ 2.86
第4步 查表：单侧 p ≈ 0.0021 < 0.05 ⇒ 拒绝H₀
结论：红色按钮转化率显著更高，相对提升 = 0.012/0.040 = +30%
```

**业务解读补充**：统计显著之后还要算钱——假设日均10万访客、客单价100元，+1.2pp转化≈日增1.2万GMV，收益可观才值得全量。这一句"算钱"是校招面试从60分到85分的关键动作。

### 3.7 置信区间：比p值更好用的表达

95%置信区间的正确读法：**用同样的抽样方法反复构造区间，其中95%会覆盖真值**（不是"真值有95%概率在区间内"，频率学派真值固定）。业务上优先报"相对提升+置信区间"：如"提升+30%，95%CI [9%, 54%]"——区间整体在0以上⇒显著；区间很宽⇒样本不足；区间下界9%≥5%⇒最小可检测效果（MDE）达成。**【加分点】** 用CI替代裸p值汇报，是资深分析师的标志。

### 3.8 本节面试问答速查

1. **p值是什么？** （按3.2定义+一句业务翻译+补CI）
2. **第一类/第二类错误在AB测试里对应什么业务后果？** 第一类=上线无效改动浪费流量与开发资源甚至伤害体验；第二类=错过本来有效的改动。
3. **为什么实验前要算样本量？** 保证功效≥80%，否则"不显著"无法解读（是没效果还是没测出来？）——样本量公式见第四节AB测试。
4. **t检验和z检验什么时候用哪个？** 总体方差未知、用样本方差替代时用t（小样本t分布更厚尾）；比例差异大样本用z（等价于卡方）。样本量大时t≈z。
5. **统计显著就能上线吗？** 还要过三关：业务显著性（提升幅度值不值）、实验健康度（样本比例偏差/新奇效应/看板口径）、长期影响（护栏指标：留存、投诉、毛利）。

## 第四节 AB测试全流程：把"我认为"变成"数据证明"

> AB测试是校招面试中统计学的最大落点，业务面与技术面都会考。完整掌握"设计→执行→解读"全链路，是区分"背过AB测试"和"做过AB测试"的分水岭。以下流程按真实工作顺序展开。

### 4.1 AB测试完整八步流程

1. **明确实验目的与假设**：不是"试试新功能"，而是"假设：在结算页增加运费透明化提示，可降低因运费疑虑导致的流失，提升支付转化率≥0.5pp"。
2. **选定核心指标（OEC）+ 护栏指标**：核心指标=支付转化率；护栏指标=订单取消率、客诉率、GMV（防"转化率涨了但客单价崩了"）。
3. **计算样本量与实验时长**：见4.4。同时预留至少覆盖一个完整业务周期（7天起，覆盖工作日/周末波动）。
4. **设计分流**：用户级随机（按user_id哈希取模），保证两组人群同质；多实验并行时用**分层正交**（流量层互相独立）。
5. **灰度上线与健康检查**：先小流量（1%）验证埋点数据正确、页面正常；跑AA测试确认两组无显著差异（AA显著=分流或埋点有bug）。
6. **正式开闸**：放量到目标流量（如各10%），**中途不改策略、不提前偷看结论**（见4.6）。
7. **到期分析**：核心指标显著性+置信区间+护栏指标检验+分人群异质性分析（新老用户/渠道，看是否有"总体平但某人群暴跌"）。
8. **决策与沉淀**：全量/回滚/迭代二版；把结论（含效应量）沉淀进实验记录库，避免重复踩坑。

### 4.2 指标设计：核心指标选不对，实验白做

- **核心指标要"因果距离近"**：改结算页就盯支付转化率，而不是盯北极星GMV（链条太长、噪声大、要数倍样本才能显著）。
- **警惕"代理指标陷阱"**：优化点击率可能带来标题党，点击涨了、转化跌了——所以护栏指标不是可选项。
- **多指标怎么下结论？** 原则：核心指标显著提升且护栏不显著恶化⇒可全量；核心涨、护栏跌⇒算总账（收益能否覆盖损失）再决策；核心不显著⇒看方向和CI，决定延长实验还是放弃。**【面试高频】**

### 4.3 随机化单元与分流细节

- **随机化单元**：绝大多数场景用"用户/设备ID哈希"而非"请求级随机"——同一用户必须稳定落同组，否则体验混乱且指标被稀释。
- **哈希取模的坑**：`user_id % 100` 适用于纯数字ID；字符串ID要先做稳定哈希（如MD5后取模）。面试常问"怎么保证100个分桶流量均匀"：先跑AA测试验证桶间均匀性。
- **正交分层**：推荐算法实验和UI实验要同时进行时，两层的桶编号独立（层间正交），保证A实验的分组在B实验维度上是随机打散的。**【加分点】** 能画出"域-层-桶"结构图的一律加分。
- **同一用户体验互斥**：同一页面的两个改动必须放同层互斥，避免叠加出混乱结果。

### 4.4 样本量计算（必会手算）

两比例比较的每组样本量公式：

$$n = \frac{(z_{\alpha/2} + z_\beta)^2 \times [p_1(1-p_1) + p_2(1-p_2)]}{(p_1 - p_2)^2}$$

常用z值：α=0.05双侧 z=1.96；功效80% z_β=0.84；两者和的平方≈7.85。

**手算例子**：基线转化率 p₁=10%，希望检测出相对提升10%（即 p₂=11%，绝对差Δ=1pp），α=0.05双侧、功效80%：

```
n = 7.85 × [0.10×0.90 + 0.11×0.89] / (0.01)²
  = 7.85 × (0.09 + 0.0979) / 0.0001
  = 7.85 × 0.1879 / 0.0001
  ≈ 14750（每组）
```

即每组约1.5万用户。若日活实验流量只有每组2000人，则需要约8天，再乘1.2倍余量并覆盖完整周≈10-12天。**经验规律**：想检测的相对差异越小、基线越低，所需样本量爆炸式增长——这就是小流量产品"实验做不出显著"的根本原因。

### 4.5 AA测试与实验健康度

- **AA测试**：两组都跑原版。若AA都显著，说明随机分流/埋点/口径有bug，实验作废。上线前跑一次AA是成熟团队的标配。**【加分点】**
- **SRM检查（样本比例失配）**：设计5:5分流但实际样本48:52且超阈值，提示分流bug或用户选择性退出。国外大厂曾因SRM错误批量撤回实验结论。
- **数据一致性**：实验桶埋点上报率是否与对照一致（新版本可能丢埋点）。

### 4.6 实验期间的三大禁忌

1. **提前偷看（peeking）**：每天看一次p值，一显著就停——多重检验让假阳性率从5%飙升到20%以上。正解：按预估时长跑满；确需早停用序贯检验（如Group Sequential/mSPRT）。**【面试高频】**
2. **中途改策略**：改了策略两组可比性即被破坏，只能作废重来或按"变点"分段分析。
3. **多重检验不校正**：同时比较20个指标，总有人"碰巧显著"。校正方法：Bonferroni（α/n）或预先声明主指标只有一个。

### 4.7 解读与决策：统计显著之后的四连问

1. **效应量多大？** 提升幅度+CI，与最小可接受提升（MDE）比。
2. **分人群有没有反向？** 总体显著但老用户跌5%——可能是新客红利掩盖了老客伤害，决定是否定向放量。
3. **有没有新奇效应？** 新按钮前3天点击虚高，看第2-3周衰减后的稳态。
4. **护栏指标和长期指标呢？** 短期转化↑但7日留存↓的改动（如过度弹窗）是亏本生意。

### 4.8 没有AB条件的场景怎么办（准实验）

很多校招实习生面对的现实是"没法AB"（大促、改版全量上线、线下门店）。备选方法：

- **前后对比+对照组**：DID（双重差分）思想——用未受影响的相似对象作对照，扣除大盘自然波动；
- **合成控制**：多个相似门店/地区加权合成"虚拟对照组"；
- **倾向得分匹配（PSM）**：非随机分组时按特征匹配可比人群；
- **【避坑指南】** 面试讲准实验时必须主动承认局限："无法完全排除混杂因素，结论是相关性偏因果的估计，我通过X/Y做稳健性检验"——诚实标注证据等级是高分信号。

### 4.9 本节面试问答速查

1. **完整讲一次你做过的AB测试**：按4.1八步讲，重点讲样本量计算、护栏指标、一个坑（如SRM或新奇效应）及修复。
2. **实验不显著怎么办？** 先查实验健康度（SRM/AA/埋点）→ 看功效是否足够（样本量是否达标）→ 看CI方向与幅度（方向对但CI宽→延长或加流量）→ 分人群看是否存在被平均掉的局部显著 → 都不行则记录结论避免重复试错。
3. **流量不够怎么做实验？** 缩小改动范围提高预期效应量；用灵敏度更高的代理指标；延长周期；换准实验设计；或者接受"测不出小效应"，只上线高置信改动。
4. **为什么不建议实验跑很久？** 样本量够即可停（按周期算而非越久越好）；跑太久会引入 cookie删除/用户学习效应/季节混杂，且错过业务窗口。
5. **AB测试和灰度发布的区别？** 灰度是工程发布策略（逐步放量防事故），不保证统计可比；AB是带随机分流的科学实验。灰度可以作为AB的前置步骤。

## 第五节 抽样方法：用一部分代表全体

> 全量数据时代为什么还考抽样？三个现实原因：问卷调研只有样本；离线分析大表先抽样试探；用户访谈/焦点小组天然是样本。面试考两类：**方法选型**与**样本量估算**。

### 5.1 五种基本抽样方法

| 方法 | 做法 | 优点 | 缺点 | 典型业务场景 |
|---|---|---|---|---|
| 简单随机抽样 | 每人等概率入样 | 无偏、简单 | 小样本可能漏掉小群体 | 从订单表随机抽1%验证数据质量 |
| 分层抽样 | 先分层（如按城市等级/新老客），层内随机 | 保证小群体代表性、精度更高、可做层间对比 | 需事先知道分层信息 | 用户满意度调研按新老客分层（新客仅5%，简单随机可能抽不到） |
| 整群抽样 | 以自然群体为单位整群抽取 | 实施成本低（按门店/班级抽） | 群内相似度高，误差大于简单随机 | 抽20家门店做客流盘点，而非全国散抽 |
| 系统抽样 | 排序后每隔k个抽1个 | 实施快 | 若排列有周期性会引入偏差 | 流水线质检每50件抽1件 |
| 便利抽样 | 怎么方便怎么来 | 快 | 严重偏差，只能做探索 | 扫楼道问卷——**【避坑指南】用于正式结论必被批** |

### 5.2 样本量估算（两类公式）

**估计均值**（如平均客单价，允许误差E、总体σ）：

$$n = \left(\frac{z_{\alpha/2} \cdot \sigma}{E}\right)^2$$

例：估计平均客单价，σ≈40元，希望误差≤2元，95%置信：n=(1.96×40/2)²≈1537人。

**估计比例**（如满意度比例，最保守用 p=0.5 使方差最大）：

$$n = \frac{z_{\alpha/2}^2 \cdot p(1-p)}{E^2}$$

例：估计满意度比例，误差≤3%、95%置信：n=1.96²×0.25/0.03²≈1067人——这就是"千份问卷"惯例的数学来源。总体很小时（如N=2000）需乘有限总体校正因子，面试提一句即可。**【面试高频】**

### 5.3 抽样偏差的四大来源（比公式更重要）

1. **覆盖偏差**：抽样框漏人——App内调研永远覆盖不到流失用户（恰恰是最想了解的人群）。改法：用短信/外部渠道触达补样本。
2. **自愿响应偏差**：主动填问卷的是极端满意/不满用户，满意度问卷均分虚低或虚高；正解是随机触达+激励。
3. **幸存者偏差**：分析"活跃用户为什么活跃"前，先问"沉默用户为什么沉默"。
4. **无响应偏差**：发1万份回收800份，回收率8%，没回的人与回的人不同质；要对比回收人群画像 vs 全量画像。

**【加分点】** 面试被问"如何做一份靠谱的用户调研"，答出"分层抽样+随机触达+回收率与无响应偏差检查+预调研校准问卷"四件套，远超"设计好问卷发出去"的平均水平。

### 5.4 本节面试问答速查

1. **分层抽样比简单随机好在哪？** 强制覆盖小群体、降低层内方差带来的估计误差、还能顺带得到分层结论。
2. **为什么比例样本量公式按1067人算就够，和总体1000万人无关？** 样本量取决于置信度、误差与方差，与总体大小无关（除非总体很小需校正）——这是最反直觉也最常考的一点。
3. **线上大数据还需要抽样吗？** 全量计算成本高时先抽样探索（如1%用户看行为路径），确认方向后全量验证结论；但注意重用户（行为多）在简单随机下被天然加权，需明确"按用户抽样"还是"按事件抽样"。

## 第六节 常见统计悖论与陷阱：面试官手里的"照妖镜"

> 悖论题是校招面试的"区分度担当"。它们不考计算，考**你对数据生成过程的理解**。以下5个必须能"讲案例+说原因+给防法"。

### 6.1 辛普森悖论（Simpson's Paradox）【面试高频第一位】

**定义**：分组内每个组的趋势，在合并后反转。

**经典案例**：AB测试中整体看B版转化率5.0% > A版4.8%；但分渠道看，iOS上A(6%)>B(5%)、Android上A(4%)>B(3%)——每个渠道都是A更好，合起来却是B更好。原因是**权重**：B恰好把更多流量分到了"高转化渠道iOS"。

| 渠道 | A版 | B版 |
|---|---|---|
| iOS（高转化） | 6.0%（占30%流量） | 5.0%（占70%流量） |
| Android（低转化） | 4.0%（占70%流量） | 3.0%（占30%流量） |
| 合计 | 6%×0.3+4%×0.7=**4.6%** | 5%×0.7+3%×0.3=**4.4%** |

**为什么会发生**：混杂变量（渠道）与分组分配相关，且与结果相关——结构效应压倒了组内效应。

**防法三件套**：① 实验分流保证人群同质（正规AB天然免疫辛普森）；② 观察性数据一律"先分层看、再看整体"，两层结论打架时以分层为准并报告权重；③ 汇报永远带结构（渠道/人群占比），裸的"整体均值"不上台面。

### 6.2 幸存者偏差

**定义**：只统计"活下来/被看到"的样本，结论系统性偏乐观。

**业务案例**：分析"高频复购用户画像"指导拉新——但拉来的人未必具备同样的生存条件；二战飞机装甲的故事（返航飞机弹孔在机翼→该加固的其实是弹孔少的发动机，因为发动机中弹的飞机没能返航）；分析老产品的留存好，可能只是因为它筛掉了不匹配的用户。

**防法**：任何用户分析先问"沉默/流失/没被统计到的人在哪"；对比口径尽量用**同期群（cohort）**而非"现存用户"。

### 6.3 回归均值

**定义**：极端表现后跟一次接近平均的表现，是随机性的必然，不是干预的效果。

**业务案例**：某店铺上月销量暴跌50%（暴雪），本月自动"回升30%"——运营把回升归功于新活动。真相：暴跌本身是极端事件，回升大概率是均值回归。**防法**：评估干预效果必须有对照组（DID），只看前后差分必被均值回归污染。校招常考形式："业绩差的团队被培训后好转，能证明培训有效吗？"

### 6.4 相关不等于因果

三类经典陷阱：
- **混杂因子**：冰淇淋销量与溺水人数正相关（共同原因：夏天）。
- **反向因果**：用户满意度高导致使用多，还是使用多导致满意度高？观察数据难分。
- **选择偏差伪装成相关**：伯克森悖论——只在"至少满足一个条件"的人群里统计，会让两个独立因素呈现虚假负相关（如"颜值高的影评更刻薄"可能只是采样于热门差评区）。

**业务正解链**：观察数据发现相关 → 提出因果假设 → 找混杂变量做分层/匹配 → 有条件就上AB实验 → 无条件用DID/PSM等准实验 → 汇报时明示证据等级。**【加分点】** 能说出"因果推断三问：有没有混杂？方向对不对？是不是选择偏差？"

### 6.5 基础比率谬误

**定义**：忽略先验概率（基础比率），只看条件概率。经典：某病患病率0.1%，检测准确率99%，某人检测阳性，患病概率是多少？直觉说99%，实际约9%：

```
10000人中：患者10人，检出阳性≈9.9人；健康9990人，误报≈99.9人
阳性者中真患病比例 = 9.9/(9.9+99.9) ≈ 9%
```

**业务对应**：风控模型"命中规则的都是坏人"的错觉——规则命中率1%、误报率0.1%，看似精准，但在1亿正常用户基数下误报绝对数远超真命中。防法：评估规则/模型永远看**精确率（Precision）而非只看召回/准确率**，并用业务基础比率心算一遍。**【面试高频】**

### 6.6 悖论防御清单（内化为分析习惯）

1. 看到任何"整体指标变化"，先拆结构（渠道/人群/品类）再下结论——辛普森防御；
2. 任何"用户画像结论"，先问样本怎么来的、沉默者在哪——幸存者偏差防御；
3. 任何"干预后好转"，先找对照组——回归均值防御；
4. 任何"两指标相关"，先列可能的共同原因与方向反转——因果防御；
5. 任何"模型/规则抓得准"，先套基础比率算绝对数——基础比率防御。
