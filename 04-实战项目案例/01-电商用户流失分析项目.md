## 一、项目背景与目标

**业务设定**：某综合电商平台（月活约800万，主营服饰+百货+数码），近3个月**月度用户流失率从18%上升到26%**（流失定义：连续90天无任何主动行为）。用户增长团队希望回答三个问题：

1. **流失发生在哪类人身上**——是全盘恶化还是特定人群恶化（渠道/新老客/品类偏好/价值层级）？
2. **流失前有没有可识别的信号**——流失用户在"最后活跃期"的行为和留存用户有什么差异？
3. **钱该往哪花**——哪些人值得召回（ROI为正）、用什么方式召回？

**项目产出目标**：一份流失监控看板口径 + 一份分层召回策略建议（含预期收益测算）。

**【避坑指南】** 校招项目最忌"一上来就跑模型"。真实工作第一步永远是**和业务对齐流失定义**（本项目的90天口径依据：平台用户平均购买间隔的中位数约为45天，取其约2倍即90天无主动行为≈大概率不再回来；并用敏感性检验验证60/90/120天口径下结论方向一致）。

## 三、分析框架

采用"**定义 → 拆解 → 归因 → 分层 → 策略**"五层框架：

```
1. 定义层：流失口径（90天）+ 敏感性检验
2. 拆解层：流失率按 渠道 / 新老客 / 会员等级 / 品类偏好 / 设备端 多维拆分，定位恶化最快的人群
3. 归因层：流失用户"最后活跃期"（流失前7/14/30天）行为对比留存用户 → 找前置信号
4. 分层层：结合RFM与流失概率，输出"召回优先级矩阵"（值得召回 × 容易召回）
5. 策略层：分层召回方案 + 成本收益测算 + AB验证设计
```

## 四、数据清洗（Python）

```python
import pandas as pd
import numpy as np
from datetime import timedelta

# ========== 1. 读取 ==========
action = pd.read_csv('user_action.csv', parse_dates=['dt'],
                     dtype={'user_id': str})            # ID读str防精度丢失；dt直接解析为日期
orders  = pd.read_csv('orders.csv',  parse_dates=['pay_time'], dtype={'user_id': str})
users   = pd.read_csv('users.csv',   parse_dates=['register_dt'], dtype={'user_id': str})

# ========== 2. 基础体检 ==========
print(action.info())                                       # 类型/缺失总览
print(action['action'].value_counts(dropna=False))         # 行为类型分布——异常值/脏值在这里暴露
print(orders['status'].value_counts(dropna=False))

# ========== 3. 清洗行为表 ==========
action = action.drop_duplicates(subset=['user_id', 'dt', 'action', 'category'])
# 用户×日期×行为类型×品类 唯一（埋点重复上报去重）；如需保留次数可改为聚合计数
action = action[action['action'].isin(['view', 'search', 'cart', 'order', 'pay'])]
# 过滤埋点异常值（如 'click_test'），口径内只留五类主动行为
action['channel'] = action['channel'].str.strip().str.upper()   # 渠道标准化（大小写/空格）

# ========== 4. 清洗订单表 ==========
orders = orders.drop_duplicates(subset=['order_id'], keep='last')   # 订单号唯一，取最新状态
valid = orders[orders['status'].isin(['已支付', '已完成'])].copy()    # 有效支付口径（剔除纯退款单）
valid['amount'] = pd.to_numeric(valid['amount'], errors='coerce')
valid = valid[valid['amount'].notna() & (valid['amount'] >= 0)]      # 金额异常单剔除并另行记录

# ========== 5. 构建用户×日 活跃宽表（后续所有分析的地基） ==========
daily = (action.groupby(['user_id', 'dt'])
               .agg(active=('action', 'size'),                       # 当日行为次数
                    has_pay=('action', lambda s: int(s.isin(['pay', 'order']).any())))
               .reset_index())                                       # 当日是否下单/支付（0/1）
daily = daily.merge(users[['user_id', 'register_dt', 'member_level']],
                    on='user_id', how='left', validate='many_to_one') # 挂用户属性（防维表重复）
daily = daily.merge(action[['user_id', 'dt', 'channel', 'device']].drop_duplicates(),
                    on=['user_id', 'dt'], how='left')
print('活跃宽表行数:', len(daily), ' 用户数:', daily['user_id'].nunique())
```

**清洗要点复盘（面试口述用）**：①ID全部读作字符串；②埋点去重到"用户×日×行为×品类"粒度；③只保留口径内五类主动行为；④订单取最新状态并过滤有效支付；⑤产出"用户×日"活跃宽表——它是留存、流失、间隔分析共用的地基表。

## 五、核心分析过程

### 5.1 第一步：确认流失率恶化是真实的（数据质检+口径敏感性）

```python
OBS_END = pd.Timestamp('2024-06-30')   # 观察窗口结束日（数据截止）

def churn_rate(df, asof, days):
    """asof前注册、且在asof-days到asof之间至少活跃过1天的用户中，
    asof之后days天内再无活跃的比例"""
    window_start = asof - timedelta(days=days)
    base = df[(df['dt'] >= window_start) & (df['dt'] <= asof)]['user_id'].unique()
    future = df[(df['dt'] > asof) & (df['dt'] <= asof + timedelta(days=days))]['user_id'].unique()
    return 1 - np.isin(base, future).mean()

# 敏感性检验：不同流失天数口径下的月度趋势（结论是否方向一致）
for k in [60, 90, 120]:
    rates = [churn_rate(daily, OBS_END - timedelta(days=30*i), k) for i in range(6)]
    print(f'{k}天口径，近6个月流失率:', np.round(rates, 3))
# 输出示意：60天:[0.31,0.30,0.32,0.34,0.37,0.39] 90天:[0.18,0.18,0.20,0.22,0.24,0.26]
#           120天:[0.12,0.12,0.13,0.15,0.17,0.19] → 三种口径下趋势一致上升，结论稳健
```

**结论1**：三种口径下流失率均持续上升（90天口径从18%→26%），排除"口径 artifact"，异动真实。

### 5.2 第二步：多维拆解，定位恶化最快的人群

```python
# 流失标记：观察窗口内活跃、之后90天无活跃 → churn=1
last_active = daily.groupby('user_id')['dt'].max().rename('last_dt')
base_users = daily[daily['dt'] <= OBS_END - timedelta(days=90)]['user_id'].unique()  # 有完整观察期的人
info = last_active.reset_index()
info = info[info['user_id'].isin(base_users)]
info['churn'] = (info['last_dt'] < OBS_END - timedelta(days=90)).astype(int)

# 挂上画像维度（取用户最后活跃时点的渠道/等级）
profile = daily.sort_values('dt').groupby('user_id').agg(
    channel=('channel', 'last'), device=('device', 'last'),
    member_level=('member_level', 'last'), n_active_days=('dt', 'nunique'))
info = info.merge(profile, on='user_id')

# 分维度流失率对比（近两期对比，看"恶化速度"而不只看绝对水平）
info['cohort'] = np.where(info['last_dt'] < OBS_END - timedelta(days=180), 'H1(半年前)', 'H2(近半年)')
pivot = info.pivot_table(index='channel', columns='cohort', values='churn', aggfunc='mean').round(3)
pivot['恶化幅度'] = (pivot['H2(近半年)'] - pivot['H1(半年前)']).round(3)
print(pivot.sort_values('恶化幅度', ascending=False))
```

**结论2（模拟数据结果）**：信息流渠道流失率从22%→34%（恶化+12pp，其余渠道+3~5pp）；**金卡会员流失率从8%→15%**（高价值人群恶化最值得警惕）；新老客结构看，流失增量主要来自**注册3个月内的次新用户**。→ 三条线索并行：信息流渠道质量、高价值会员体验、次新用户激活。

### 5.3 第三步：流失前置信号（最后活跃期行为对比）

```python
# 对每个流失用户，取其流失前14天为"临终窗口"；对活跃用户取最近14天为对照窗口
sig = daily.merge(last_active.reset_index(), on='user_id')
sig['win_end'] = np.where(sig['churn']==1, sig['last_dt'], OBS_END)
sig['win_start'] = sig['win_end'] - timedelta(days=14)
win = sig[(sig['dt'] >= sig['win_start']) & (sig['dt'] <= sig['win_end'])]

feat = win.groupby('user_id').agg(
    days=('dt', 'nunique'),                       # 活跃天数
    search_cnt=('dt', 'size'),                    # 行为总量
    cart_rate=('action', lambda s: s.isin(['cart','order','pay']).mean())  # 深度行为占比
).reset_index()
feat = feat.merge(info[['user_id','churn']], on='user_id')

report = feat.groupby('churn')[['days', 'search_cnt', 'cart_rate']].mean().round(3)
report.index = ['留存用户', '流失用户']
print(report)
# 输出示意：流失用户最后14天活跃天数2.1 vs 留存5.8；cart_rate 0.06 vs 0.19
#          且流失前最后3天"只浏览不搜索"占比显著升高
```

**结论3（信号解读）**：流失不是"突然消失"而是"**先降温再离开**"——最后14天活跃天数骤降、深度行为占比（加购/支付）萎缩到留存用户的1/3；最后的显著行为是"只浏览不搜索"，指向"没有找到想买的东西"（货不对板）而非"服务不满"。→ 召回素材应主打"货找人"（新品/降价提醒），而非泛券。

### 5.4 第四步：召回优先级矩阵（RFM × 流失概率）

```python
# 用 RFM 三维打分（价值）× 流失前信号（回归倾向）切四象限
feat2 = feat.merge(info[['user_id','member_level']], on='user_id')
feat2['value_score'] = pd.qcut(feat2['search_cnt'], 4, labels=[1,2,3,4]).astype(int)  # 活跃强度代价值

# 简化版倾向打分：临终窗口深度行为占比越高越"容易唤回"（有购物意图）
feat2['recall_potential'] = pd.qcut(feat2['cart_rate'], 4, labels=[1,2,3,4]).astype(int)

matrix = feat2[feat2['churn']==1].pivot_table(
    index='value_score', columns='recall_potential', values='user_id', aggfunc='count')
print(matrix)
# 四象限策略：高价值高潜力=定向大额券+专属客服；高价值低潜力=短信+品类降价推送
#            低价值高潜力=push+小额券批量；低价值低潜力=不投入（自然流失）
```

### 5.5 第五步：收益测算与AB验证设计

- **测算逻辑**：召回ROI = 召回率 × 召回用户90天预期毛利 − 触达成本。模拟参数下，"高价值高潜力"层（约2.3万人）：短信+大额券人均成本1.2元、预估召回率12%、召回用户90天毛利中位数45元 → 期望ROI≈45×0.12/1.2≈**4.5倍**；"低价值低潜力"层ROI≈0.3倍，不投入。
- **AB设计**：各分层内随机分流10%为对照组（不触达），跑4周，核心指标=召回率与召回后次月留存，护栏=退订率与投诉率。

## 七、业务建议（落地方案）

1. **渠道治理（止血）**：给信息流渠道设"新客次留≥25%"的考核门槛，未达标渠道降预算；媒体侧排除低质素材。
2. **高价值会员挽留（最优先）**：金卡会员流失率翻倍是重大预警——上线"会员权益使用率监控"，对90天未用权益的金卡会员触发专属客服回访+定向权益包。
3. **次新用户激活**：注册30-60天未复购用户自动进入"货找人"召回流（基于浏览品类的降价/新品推送），替代当前的全量泛券（泛券ROI测算仅0.8倍）。
4. **流失预警机制**：将"最后14天活跃天数降幅>50% 且 深度行为占比<10%"定义为高危信号，接入实时看板，运营每周处理高危名单。
5. **效果验证**：所有召回动作分层AB，4周复盘召回率/次月留存/ROI，迭代素材与券面额。

**预期收益（测算口径透明）**：若分层召回使高价值层召回率达成12%，按90天毛利测算，年化挽回GMV约占总流失GMV的8-10%，扣除成本净收益约为触达预算的3-4倍。

**面试追问预演（6问+答题要点）**：

1. **流失为什么定90天？** 平均购买间隔中位数45天的约2倍+三种口径敏感性检验方向一致；真实业务会与运营对齐。
2. **为什么不用机器学习模型预测流失？** 样本量与特征工程成本下，规则信号（活跃降幅+深度行为占比）已能解释主要模式且可解释可落地；模型是下一步迭代方向（提逻辑回归/GBDT做概率分层）。
3. **怎么保证"最后14天行为差异"不是因果颠倒？** 明确这是**前置信号（相关性）**而非因果；验证方式是前瞻性验证——用信号在T时点预测T+90流失，而不是用结局反推。
4. **召回ROI测算的假设可靠吗？** 全部参数（召回率、毛利中位数、成本）列出敏感性区间；结论用AB实测校准，测算仅用于优先级排序。
5. **如果老板说"全员发券唤醒"更简单？** 用数据说话：泛券ROI测算0.8倍<1，且高价值层定向ROI 4.5倍——同样预算下分层方案的期望收益高5倍以上，并提议先小流量AB对比两种方案。
6. **项目最大的坑是什么？**（诚实加分题）埋点行为表存在重复上报，最初计算的活跃天数虚高约8%——发现过程（价值分布异常）与修复（按用户×日×行为去重）讲清楚，体现数据严谨性。
